IMPORTANT: This file separates source-code checks from Strapi role grants.
The source controls the role and record checks listed below. Strapi Users &
Permissions action grants are stored in the MySQL database, not in this source
tree. A role must have the action enabled before its authenticated request can
reach a protected custom route. A valid JWT without an action grant can be
rejected by Strapi. Missing/invalid user identity or a denied role action may
produce 401 or 403 depending on which Strapi layer rejects the request.

AUTHENTICATION TYPES
--------------------
Browser/staff sessions use a Strapi user JWT. Controllers that read
ctx.state.user require this user identity.

APIACCESSTOKEN is a Strapi API token, not a user JWT. It can authorize
machine-to-machine API requests, but it does not create ctx.state.user or
represent an owner, manager, waiter, or platform master. Do not put it in the
frontend or use it to test a user-only custom controller.

SOURCE-ENFORCED CUSTOM ROUTE MATRIX
----------------------------------
The matrix below describes controller rules. For protected routes, Strapi
must also grant the route action to the caller's Users & Permissions role.
Business scope means the caller's active employee record must belong to the
requested business. Branch scope means the manager is limited to their branch.
